**Two defects, found on the way in — both disclosed rather than worked around.**

1. **The on-ramp is unpassable on Node ≥ 26 as shipped.** `init()` (`src/gate/sign.js`) builds the approval private key as an OKP JWK with an empty public half, `{ crv: 'Ed25519', d, x: '', kty: 'OKP' }`. Node 26 rejects it — and so do `x` omitted and `x: null` — with `Invalid JWK OKP key`. The catch is structural: Node requires a valid `x` beside `d`, and `x` is precisely what has not been derived yet. So step 4 cannot be completed at all. The signing path (`createApprovalToken`) passes a real `x` and is unaffected. **This install is locally patched**: `init()` now derives through PKCS#8 (fixed prefix `302e020100300506032b657004220420` + the 32-byte PBKDF2 seed) instead of JWK. One block, in my own clone; nothing upstream was touched. A receipt from a patched tool has to say so, so it does — and for a checker who hashes the tree, the session-open entry's `observer.build.sourceDigest` is `edd8e828a57fa3af2968f76d4849fd9993c336ffdfd955f4b5c74992f8c0f4ad` over 53 files / 560,985 bytes, which is a digest of the **patched** tree and will not match upstream commit 1720aa1.
